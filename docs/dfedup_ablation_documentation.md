# DFedUP 算法设计与消融矩阵文档

> **文档目的**: 记录 DFedUP 算法在 Ray 分支下的完整重构逻辑，定义并分析 13 个用于消融实验的变体版本。

---

## 1. 核心算法概览 (DFedUP - Final)

DFedUP 是一个基于 **Push-Sum 协议** 和 **去中心化原型共识** 的个性化联邦学习算法。

### 1.1 关键技术组件
*   **质量守恒 Push-Sum**: 使用列随机矩阵 $M$ 驱动状态演化，解决非对称拓扑下的权重偏差。
*   **语义原型桥梁**: 客户端提取本地原型并上传 $S$ (累积特征) 和 $W$ (累积计数)，通过全图 Gossip 形成类级别的共识语义。
*   **两阶段解耦优化**:
    *   **Phase 1 (Classifier Calibration)**: 冻结提取器，利用共识原型校准分类器决策边界。
    *   **Phase 2 (Extractor Alignment)**: 冻结分类器，使特征提取器向全局流行靠拢。

## 3. 详细变体说明

### [dfedup.py](../src/algorithms/dfedup.py) - 旗舰版本
*   **特征提取器聚合**: 仅共享表示能力，保留分类器的个性化（隐私）。
*   **原型对齐**: 客户端在训练中受共识原型约束。
*   **两阶段**: 顺序执行“校准 -> 对齐”。

### [dfedup1.py](../src/algorithms/dfedup1.py) - 联合训练版
*   将两阶段合并为单阶段联合优化，取消参数冻结逻辑。
*   用于证明：分阶段优化能够减少表示层与决策层在 Non-IID 场景下的冲突。

### [dfedup2.py](../src/algorithms/dfedup2.py) - 纯参数聚合版
*   删除了所有原型相关逻辑（无 $S/W$ 缓存，无原型对齐损失）。
*   演变为一个标准的去中心化 PFL 算法，用于作为最底层的 Baseline。

### [dfedup3.py](../src/algorithms/dfedup3.py) - 原型单一驱动版
*   完全不传输模型参数，每个客户端的模型在本地演化。
*   唯一的协作方式是通过 Push-Sum 交换类原型。这可以验证“语义对齐”是否足以纠正本地偏移。

### [dfedup4.py](../src/algorithms/dfedup4.py) - 角色反转版
*   特征提取器保持私有，分类器进行 Push-Sum 聚合。
*   该版本测试：在 Non-IID 场景下，对齐“决策边界”是否比对齐“表示能力”更有效。

### [dfedup5.py](../src/algorithms/dfedup5.py) - 联合训练 (PLN版)
*   **训练策略**: 取消了分阶段训练，将本地 CE、共识锚定与特征对齐合并为单次联合优化。
*   **聚合范围**: 与 `dfedup8` 一致，仅聚合 PLN 参数，模型完全个性化。
*   **目的**: 验证在引入 PLN 神经网络表征原型后，是否仍需要像 `dfedup` 那样进行复杂的两阶段解耦优化。

### [dfedup6.py](../src/algorithms/dfedup6.py) - 极致轻量版
*   **极简聚合**: 仅对模型的第一层卷积进行 Push-Sum 聚合。
*   **目的**: 测试仅对齐最基础的视觉特征（如边缘、纹理）是否足以支撑联邦协作。

### [dfedup7.py](../src/algorithms/dfedup7.py) - 浅层共享版
*   **扩展聚合**: 聚合范围扩大至前两个卷积层。
*   **目的**: 在 `dfedup6` 的基础上观察增加浅层参数共享对精度的提升，进一步探索通信与精度的折中。

### [dfedup8.py](../src/algorithms/dfedup8.py) - PLN 原型学习版
*   **不再直接传输原型**: 使用一个小型神经网络 (PLN) 来学习和表征原型。
*   **PLN 参数共识**: 通过 Push-Sum 交换 PLN 的权重。
*   **目的**: 结合了 `FedDPC` 的思想，通过神经网络的拟合能力来平滑 Non-IID 环境下的原型噪声，提高共识的鲁棒性。

### [dfedup9.py](../src/algorithms/dfedup9.py) - 双重协作版
*   **特征提取器聚合**: 采用 **普通平均聚合 (Simple Gossip)**。
*   **原型聚合**: 采用 **PLN + Push-Sum**。
*   **训练策略**: 联合训练。
*   **设计逻辑**: 试图结合 `DFedUP1` 的表示层共享优势与 `DFedUP8` 的高效语义对齐。

### [dfedup10.py](../src/algorithms/dfedup10.py) - 协议消融版
*   **核心逻辑**: 在 `DFedUP1` 的基础上，将特征提取器的聚合协议从 **Push-Sum** 降级为 **普通平均聚合 (Simple Gossip)**。
*   **目的**: 专门对比在特征层共享时，Push-Sum 的“质量守恒”特性是否对最终精度有显著贡献。

### [dfedup11.py](../src/algorithms/dfedup11.py) - 原型普通聚合版
*   **核心逻辑**: 特征层保留 Push-Sum，但原型共识降级为普通平均聚合。
*   **目的**: 探究原型共识对拓扑权重偏差的敏感度。

### [dfedup12.py](../src/algorithms/dfedup12.py) - 全量普通聚合版
*   **核心逻辑**: 彻底抛弃 Push-Sum，所有协作层均使用双随机矩阵进行 Gossip 平均。
*   **目的**: 建立非 Push-Sum 体系下的基准，评估 Push-Sum 在整个算法体系中的核心价值。

## 4. 参数复用说明 (Hyperparameter Usage)

为了简化实验配置，所有版本均复用以下现有参数：
*   **`epochs`**: 核心迭代轮数。在两阶段变体（如 `dfedup`）中，Phase 1 固定为 1 Epoch 热身，`epochs` 用于 Phase 2；在联合训练变体中，则为总训练轮数。
*   **`mu`**: 通用原型权重。在 Phase 1 用于分类器校准，在 Phase 2 用于特征对齐。
*   **`lr`**: 客户端通用学习率。

## 5. 实验结果与分析 (Results & Analysis)

基于 CIFAR-10 (Dirichlet $\alpha=0.1$, 10 Clients, Ring Topology) 的实验数据，各变体的表现如下表所示：

| 算法变体 | Max Accuracy (%) | Last 10 Avg (%) | 核心发现 |
| :--- | :---: | :---: | :--- |
| **`dfedup`** | 85.98 | 84.85 | **基准表现**，收敛稳定性适中。 |
| **`dfedup1`** | **86.59** | **85.53** | **峰值最高**，但联合训练在复杂场景下可能更易震荡。 |
| **`dfedup2`** | 85.69 | 84.55 | 纯参数聚合的表现非常接近完整版，证明了骨干网络同步的基础价值。 |
| **`dfedup3`** | 83.90 | 83.61 | **纯原型驱动**，不传模型参数也能达到 83.9%，通信性价比极高。 |
| **`dfedup4`** | 83.90 | 83.80 | 聚合分类器层，效果与纯原型驱动相当。 |
| **`dfedup5`** | 84.34 | 83.42 | 作为 `dfedup8` 的联合训练版，性能仅低 ~0.3%，说明 PLN 对训练策略有较强适应性。 |
| **`dfedup6`** | 84.01 | 83.85 | 仅聚合第一层卷积，表现竟然优于聚合分类头 (`dfedup4`)，证明浅层语义的重要性。 |
| **`dfedup7`** | 83.62 | 83.36 | 聚合两层卷积，结果略逊于一层聚合，可能存在梯度冲突。 |
| **`dfedup8`** | 84.64 | 84.11 | **PLN 表现出色**，在全个性化架构中精度最高，证明了学习型原型的优越性。 |
| **`dfedup9`** | 86.59 | 85.28 | **双重协作巅峰**，模型精度追平 `dfedup1`，证明了特征层交互对表示能力的极大提升。 |
| **`dfedup10`**| 86.68 | **86.08** | **最稳定组合**，证明特征层使用“普通平均”能减少训练抖动。 |
| **`dfedup11`**| **86.97** | 85.99 | **全系列最高精度**，暗示原型层使用“普通平均”反而能提供更好的语义泛化。 |
| **`dfedup12`**| 86.80 | 85.87 | **最轻量/高效**，全量普通平均的表现依然大幅领先于原始 `dfedup`。 |

### 5.1 PLN 版本原型精度 (Proto Accuracy) 特别记录
在 PLN 架构下，除了模型精度，我们还记录了使用 PLN 生成的原型进行分类的精度：
*   **`dfedup5 (Proto)`**: 83.78% (Max) / 82.81% (Last 10)
*   **`dfedup8 (Proto)`**: 80.36% (Max) / 79.75% (Last 10)
*   **`dfedup9 (Proto)`**: 65.88% (Max) / 64.12% (Last 10)
*   **发现**:
    1. 联合训练 (`dfedup5`) 生成的原型表征能力强于分阶段训练 (`dfedup8`)。
    2. **模型-原型双重交互 (`dfedup9`)** 虽然极大地提升了模型精度，但 PLN 的原型精度显著下降。这表明特征层的参数共享可能与 PLN 的语义共识存在一定的“表示冲突”，需要更精细的解耦。
    3. **协议组合效应 (Synergy Effect)**: 实验揭示了原型与特征层协议之间的非线性协同关系：
        *   **原型协议是精度天花板**: 只要原型层从 Push-Sum 切换为 **Simple Gossip**，模型峰值精度均有显著跃升（`11` 和 `12` 均优于 `1` 和 `10`）。这证实了原型共识不需要绝对的数学精确，平滑的平均反而有利于语义泛化。
        *   **特征层协议的补偿作用**: 在原型已实现平滑（Simple）的前提下，特征层使用 **Push-Sum** 维持权重守恒能进一步压榨精度（`11 > 12`）；但在原型较硬（PS）时，特征层使用 **Simple** 则能缓解抖动提升稳定性（`10` 的 Last 10 最高）。

### 5.2 最终结论与工程建议
1.  **最优性能组合 (`DFedUP11`)**：若追求极致精度，推荐 **“特征层 Push-Sum + 原型层 Simple Gossip”**。该组合兼顾了表示层的精确权重守恒与语义层的平滑泛化。
2.  **最高稳定性组合 (`DFedUP10`)**：若环境噪声大、追求尾部平稳，推荐 **“特征层 Simple Gossip + 原型层 Push-Sum”**。
3.  **协议设计准则**: 在去中心化 PFL 中，协议的选择不应“一刀切”。越靠近决策层的语义信息（原型），越适合平滑的 Gossip 聚合；越靠近底层的表示能力（Extractor），越适合精确的 Push-Sum 聚合。

### 5.3 核心规律总结
1.  **个性化红利**: 从全个性化方案到 `dfedup` 的性能跨越，证明了保留本地分类器对处理异构数据的决定性作用。
2.  **原型 vs 参数**: 纯参数聚合 (`dfedup2`) 表现非常稳健。然而 `dfedup3` 的结果证明，仅通过交换轻量级原型（不交换参数）也能挖掘出 Non-IID 数据中大部分共性规律，这为带宽受限场景提供了极佳方案。
3.  **两阶段稳定性**: 虽然联合训练 (`dfedup1`) 能达到相似峰值，但 `dfedup` 的尾部平均值更高，说明先校准分类器再对齐提取器的策略能有效缓解 Non-IID 带来的震荡。
4.  **协议演进**: 从 `dfedup10/11/12` 的结果看，特征提取器对 Push-Sum 的“质量守恒”并不敏感，使用 **Metropolis-Hastings 权重的普通平均聚合** 反而能提供更平滑的训练曲线。
